## 0. 一句话结论

**真正危险的，是每个页面都要从 3 个「没有 SLA 的免费托管点」拉 21 个资源**：`registry.npmmirror.com`（9 个）、`npm.elemecdn.com`（8 个，其中 3 个还是 `@latest`）、`picsum.photos`（图片）。这三个任意一个抽风，站点就进入「能打开、但样式 / 图标 / 图片全废」的状态——比某个 API 挂掉严重得多。

另外还有一个**已经失效、但很容易被忽略**的：正文里 42 处 canonical / og:url / sitemap 指向的 `www.lichengic.com`，现在在 DNS 里根本不存在。

## 3. 每个页面真实加载的外部资源（实测 `public/index.html`）

一次首页加载要向 8 个外部域名发请求：

```
registry.npmmirror.com   9 个：jquery 3.6.0 / clipboard 2.0.10 / vanilla-lazyload 17.3.1
                                 fontawesome-free 6.0.0 / @fancyapps/ui 4.0.31 ×2
                                 aplayer 1.10.1 ×2 / instant.page 5.1.0
npm.elemecdn.com         8 个：tag-plugins-plus@latest ×3 / wowjs ×3 / pace-js@1.2.4 / metingjs js-heo
cdn.jsdelivr.net         1 个：lxgw-wenkai-screen-webfont@1.7.0（CSS，再拉字体文件）
lib.baomitu.com          1 个：pjax 0.2.8
sdk.51.la                2 个：统计 + 性能
picsum.photos            3 个：日/夜/移动端背景（另有列表页封面）
api.zxki.cn              1 个：随机图
at.alicdn.com            仅预连接（不加载）
```

> 补充：`wow.js` 和 `vanilla-lazyload` 里，`wow` 其实没在页面上用（构建产物里没有 `.wow`），但 `vanilla-lazyload` **是刚需**：`data-lazy-src` 有 **520 处**，由主题 `main.js` 里的 `new LazyLoad({ data_src: 'lazy-src' })` 接管——这个库一旦起不来，全站图片就停在 1×1 占位图。
