这个博客是怎么跑起来的：Hexo、一个改过的主题，和两条部署路

发表于 2026-11-05|更新于2026-11-05|建站折腾
|字数总计:1836|阅读时长:6分钟|阅读量:—

开篇：为什么自己搭

现成平台省事，但有三件事它给不了：数据在自己手里、样式能改到像素级、想加什么功能就加什么功能。这个站从一台 Windows 机器上的一个文件夹开始，现在有十几个自建页面、几十个脚本模块，仍然是一份可以整包拷走的静态文件。

这篇不讲"Hexo 怎么装"，讲的是它到底怎么运转，以及为什么长成现在这个样子。想搭同类站点的人，可以把它当成一张施工图。

一、三层配置：改错文件是新手第一大坑

Hexo 的配置不是一份，是三份，而且是"深度合并"的关系：

机制来自 Hexo 的 alternate theme config：Hexo 会自动去找根目录的 _config.<主题名>.yml，把它合并进主题配置。所以有三个名字必须联动：

  • _config.yml 里的 theme: fomalhaut
  • themes/ 下的目录名 fomalhaut
  • 根目录的 _config.fomalhaut.yml

任何一处改名都要三处同步。不同步不会报错，但你的主题配置会静默失效，页面看起来"突然变回默认样子"，非常难查。

二、站点与主题彻底分离

这是本站和"直接改主题"的最大区别：

放什么 位置 特点
文章、页面、图片 source/ 跟主题无关，换主题不用搬
全站样式 source/css/*.css 19 个文件，各管一页或一类组件
全站脚本 source/js/ 30 个模块 + 注入脚本
主题本体 themes/fomalhaut/ Pug 模板 + Stylus，尽量少改

好处很实际：主题升级时可以整体替换，自己的东西一行不动。代价是要理解"哪些该放站点、哪些该放主题"——判断标准很简单：只跟这个站有关，放 source/；跟模板结构有关，才动 themes/。

三、页面是怎么长出来的

静态站点的"页面"其实分两类：

  1. 文章页：source/_posts/*.md，Hexo 按 permalink: posts/:abbrlink.html 生成。
  2. 独立页面：source/<名字>/index.md，front-matter 里指定 layout 或 type。

现在站上的独立页面大致是这些：

路径 做什么 实现
/archives/ 归档 主题模板
/tags/ 文章统计看板 ECharts + 自定义 JS
/music/ 音乐馆 整页自绘 + 全局播放核心
/thread/ 螺纹规格速查 纯 HTML 表格 + 筛选脚本
/macro/ 宏程序生成器 表单 + 42 个模板
/nav/ 网址导航 手写 HTML + CSS 计数
/site/time/ 旧时光（站史） 时间线标签
/links/ 友人帐 主题 flink 模板 + 随机排序
/message/ 留言板 Twikoo 评论
/about/ 关于 手写 HTML 三段式

这些页面有个共同点：能静态生成的绝不依赖后端。只有一个例外是评论和少量接口。

四、脚本是怎么组织的

source/js/ 下大致分三层：

  • 引导层：modules/shell.js、modules/settings.js 之类，负责初始化。
  • 功能层：音乐、日历、统计、阅读进度、鼠标特效、AI 面板等，一个功能一个文件。
  • 注入层：inject/*.js，在页面里按需执行的一次性补丁，比如 pjax 之后重新绑定滚动、懒加载搜索。

一个实际经验：运行期插入的 <a>，pjax 接不住。点上去会整页跳转，正在播放的音乐就断了。所以有一个 pjax-relink.js，专门给这些后插入的链接补上拦截。

五、缓存：改完看不到效果的头号原因

静态站点最常见的困惑是"我明明改了，怎么没变"。原因几乎总是浏览器缓存了旧文件。

本站的做法是版本号写在引用处，改完就推一位：

  • 页面级资源：写在页面 front-matter 或模板里。
  • 全站注入：写在 _config.fomalhaut.yml 的 inject 段。

只改文件不推版本号，等于没改。改完记得同步抬 ?v=，再 hexo clean && hexo generate。服务端如果还缓存，重启一次 hexo server。

六、部署：两条路，各有各的脾气

这个站同时存在两条发布路径，用途不同：

GitHub Pages github.lichengic.com 纯静态，构建简单，稳定

七、踩过的坑（都是真踩的）

7.1 模板语法写进了 JS 注释

source/js/ 里的文件也会被 Hexo 当模板处理。注释里写了一个 {% flink %}，构建直接报 unexpected end of file。JS 注释里不要出现 {% %}。

7.2 样式被主题覆盖

主题的 custom.css 里有三套同名的 hover 规则，都带 !important，而且加载在后面。只写同等特异性是压不过的。解决办法是抬特异性，比如 #btn#btn:hover，或者确认加载顺序。

7.3 页面切换后状态残留

pjax 只换内容不换文档，绑定在 window 上的监听会越积越多。所有全局监听都要在 pjax:complete 里重新绑定，并且先解绑。

7.4 音乐跨页就断

整页跳转会销毁 <audio> 的单例。解决办法是把播放核心挂到一个不随页面销毁的地方，并且在整页刷新时用 sessionStorage 存快照，新文档读回来接着放。

7.5 构建成功但线上没更新

先看三件事：?v= 推了没、public/ 里是不是新产物、托管平台有没有真的重新构建。Vercel 的 check suite 经常一直显示 queued，不能拿它当成功标志，要看文件的 Last-Modified。

八、给想搭同类站点的人

  1. 先跑通最小闭环：一篇文章、一个页面、一次部署。再谈样式和功能。
  2. 把配置分层，别把所有东西塞进一个文件。
  3. 版本号机制从第一天就上，能省掉一半"为什么没生效"。
  4. 能用静态解决的，别引入后端。静态站点的寿命长得多。
  5. 养成写改动日志的习惯。半年后你会感谢现在的自己。

这套东西谈不上多先进，但它足够透明：每一行样式、每一个脚本，都知道为什么在那儿。对一个个人站点来说，这比"用了什么框架"重要得多。
